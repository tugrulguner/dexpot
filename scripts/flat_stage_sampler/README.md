# Bounded request-stage sampling

Instrumented diagnostic only; no qualification or syscall/kernel/GIL attribution. The current pinned artifact is unchanged on disk. Startup wrappers sample each connection's 64th request, correlate its exact response Task through enqueue, first dispatch and completion, and capture existing first-byte availability plus preceding response completion. Task identity is retained by id because the slotted dataclass is unhashable. Bounds: 128 connections/pending samples and 10,000 rows; caps and matcher errors fail closed.

Before timing, a real keepalive connection sends 64 checked flat requests and must yield exactly the sequence-64 sample with ordered timestamps. The collector resets only when quiescent, then executes one original 15-second wrk window (4 threads, 16 connections, flat profile). It verifies serving PID/runtime, prepared versus validated native responses with at most 16 in flight, expected per-connection sample counts, zero drops and unmatched tasks, and normal cleanup. Actual matched rows and all error counters are retained.

Stages are ready-to-worker, worker-to-enqueue (parser, preparation, framing and task creation), queue age, and observed owner commit. Commit-to-next-observation additionally includes client/network/selector/read-return effects. Individual percentile values must not be summed. A sampled local queue delay is not proof of an OS/GIL cause or of a production speedup. `--control-only` exercises the real 64-request matching preflight and cleanup without native timing. Required CLI inputs mirror the existing crossover CLI: python, wheel, harness, wrk, collector and a new output directory.
