# Dexpot loopback measurement

This is a recorded local measurement, not a live playground timer and not a framework comparison. It measures completed HTTP request/response latency from `wrk` on the same Mac to Dexpot bound to `127.0.0.1`; it includes client scheduling and loopback transport, so it is not isolated server-processing time. The run is a short, single-machine smoke measurement, not a promotion-quality benchmark or a performance claim.

## Recorded run

- Endpoint: `GET /items/7` from the shipped `examples/minimal.py`; expected body `{"id":7,"name":"item-7","price":7.0}`.
- Dexpot: checkout source at base `d670aca`, Python parser (`DEXPOT_HTTP_PARSER=python`), default scheduler/pool, one process.
- Runtime: CPython 3.14.7, GIL enabled; macOS 26.5.2 (Darwin 25.5.0), Apple M4, arm64.
- Generator: `wrk 4.2.0 [kqueue]`, 2 threads, 8 persistent connections, 5 seconds; 83,430 responses checked, 0 invalid statuses/bodies. Captured output: 5.10 s elapsed, 11.70 MB read.
- One captured trial; no randomized pairing or repeated-run inference. wrk latency is request-to-response observed by the local client.
- p50 439 µs · p75 655 µs · p90 0.92 ms · p99 1.76 ms; average 515.11 µs; max 8.62 ms.
- Throughput: 16,361.16 completed requests/s; transfer 2.29 MB/s. Not a comparison against another framework or machine.

## Reproduce

From the repository root, with `wrk` installed and the checkout's uv environment prepared:

```bash
DEXPOT_HTTP_PARSER=python DEXPOT_EXAMPLE_PORT=8000 uv run python examples/minimal.py
wrk -t2 -c8 -d5s --latency -s website/benchmarks/dexpot-loopback.lua http://127.0.0.1:8000
```

The Lua script verifies every response's status and exact JSON body. `wrk` invokes scripts independently per generator thread and reports observed request latency percentiles. Results vary with system load, runtime build, power state, and hardware. Do not compare these local macOS numbers with Linux, free-threaded Python, or other frameworks as equivalent evidence.
